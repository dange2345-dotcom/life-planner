# PROJECT.md — Планер (life-planner)

Рабочий документ проекта: ТЗ, архитектура, roadmap, лог решений и следующие шаги.

## ТЗ (техническое задание)

Личное приложение-планер для одного человека (владельца). Замена платным шаблонам Google Таблиц (референс — nextplanners.ru: планеры привычек, задач, финансов; скрины: сетка привычек по дням месяца с %, кольцо «выполнено / запланировано», график % по дням, «самые стабильные привычки», еженедельные и ежемесячные привычки, цели на год по сферам).

**Устройства:** iPhone и ПК на Windows, синхронизация между ними с первого дня. iCloud и бэкап файлами — не нужны.

**Разделы:**
- **Привычки** — ежедневные / по дням недели / N раз в неделю / N раз в месяц; отметка одним касанием; % по привычке и за месяц; статистика как в референсе; серии.
- **Задачи** — проекты с подзадачами и % выполнения; задачи на день с переносом несделанных; приоритеты; календарь месяца со сроками.
- **Финансы** — расходы и доходы по категориям; цели накоплений с % и «сколько откладывать в месяц»; подписки, кредиты и регулярные платежи. Бюджет с лимитами **не нужен**.
- **Цели на год** — по сферам жизни; к цели привязываются привычки, проекты, накопления; общий % цели.
- **Напоминания** — пуш через ntfy (вечером «отметь привычки — X из Y», утром «завтра платёж»).
- **Тема** — светлая пастельная (розовый/голубой, как в референсе) + тёмная, автоматически по системе.

**Критерии готовности (этап 1):** на iPhone и на Windows установлено одно приложение; отметка привычки на одном устройстве появляется на другом; без интернета всё работает, изменения доезжают при появлении связи.

## Архитектура

- **PWA** (Vite + Preact + TS) — один код для iPhone и Windows. На iPhone — экран «Домой», на Windows — «Установить приложение» в Edge/Chrome.
- **GitHub Pages** — только хостинг файлов приложения. iPhone ставит приложение мимо App Store, только если оно открыто по HTTPS-адресу. Данных на GitHub нет. Cloudflare не используем — в России его душат с июня 2025.
- **Supabase** (бесплатный тариф) — вход по e-mail+паролю, одна таблица `records(id, user_id, kind, data jsonb, updated_at, deleted, server_updated_at)` с RLS «только свои строки». Регистрация закрыта, пользователь создан вручную. Firebase отклонён (блокируется у части провайдеров РФ), Яндекс.Диск — CORS из браузера.
- **Offline-first синхронизация:** Dexie (IndexedDB) — локальная копия; правки помечаются `dirty` и отправляются пачкой (debounce 2 с, при открытии, при возврате в окно, раз в минуту); скачивание по курсору `server_updated_at`; конфликт — побеждает более поздний `updated_at` (проверяется триггером на сервере).
- **Напоминания:** Supabase Cron (`pg_cron`) + `pg_net` → POST в ntfy (отдельный топик).

**Запасной путь:** если Supabase станет недоступен из РФ без VPN — перенести `records` в Yandex Cloud (YDB + Cloud Functions), меняется только слой синхронизации.
